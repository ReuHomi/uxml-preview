# Text cohort

The preview's text boxes, measured in a real Chromium, against Unity's for the
same UXML, fonts and sizes. A separate verification set: its numbers are never
added to the coordinate accuracy figures in `docs/accuracy.md`.

Fonts are judged by boxes and line counts, not pixels or bytes. happy-dom and
jsdom cannot measure glyphs, so this does not run under `pnpm test`.

## Run

```
pnpm test:text
```

| Variable | What |
|---|---|
| `UXML_TEXT_CHROMIUM` | Path to a Chromium executable. Unset or missing: the run prints `텍스트 코호트가 실행되지 않음` and fails — it is never skipped as a pass |
| `UXML_TEXT_FONTS` | Folder holding the font files in `spec.json` |
| `UXML_TEXT_UPDATE=1` | Print the table without checking `docs/accuracy.md` (to update the doc) |

Getting a Chromium (the one used for the published table is in `results.json`
and in the table header in `docs/accuracy.md`):

```
npx playwright@1.48.2 install chromium
```

On Windows it lands in `%LOCALAPPDATA%\ms-playwright\chromium-1140\chrome-win\chrome.exe`.

## What is in here

- `spec.json` — fonts (each with its own sentences and boundary sentences), sentences, sizes,
  boundary offsets, the wrap set, and `known` differences. `noGlyphs` marks
  sentences a font has no glyphs for (Inter has no Hangul), so a mismatch there
  is classified as a fallback-font difference, (a).
- `probes/` — the UXML/USS both sides render, generated by `gen-probes.mjs`.
  `boundary-*` cases set the box to Unity 6000.0's one-line width ±2px
  (`boundary-widths.6000.0.40f1.json`), with `white-space: normal`. Fonts with
  `boundaryFilePerSentence` get one file per sentence, so the column stays inside the
  600px panel (an overflowing column shrinks the preview's Labels; Unity's do not).
  `wrap-*` cases set fixed box widths (`spec.wrap`). The files here are the ones Unity
  measured; `gen-probes.mjs` reproduces them byte for byte.
- `unity/<version>/` — Unity dumps (probe dumper in
  `tests/layout/unity/probes-0.6.0/ProbeDump.cs.txt`), including the FaceInfo
  of the font each Label is drawn with.
- `unity-runtime/<version>/` — the runtime-panel set (0.7.0 item T, 2026-10-19): PanelDump on a real
  runtime panel, each probe in its own Unity process (`tests/layout/unity/dump-solo.sh`). Drawn with
  `theme: 'runtime'` and judged as its own table; `spec.known` keys for it start with `runtime `.
- `results.json` — the last run.

## Criteria

- line count: must match
- height: must match the FaceInfo formula exactly
- width: within 1px or 1% of Unity; the spread is reported
- line-break cases (boundary `-bm2`/`-bp2` and wrap `-wN`): line count, in their own column

A failure is classified (a) font/text metrics — including fallback glyphs and
6000.0's measured height rule —, (b) within 1px, (c) unexplained. Any (c) fails
the run.

A line-count flip is (b) only on a boundary case whose preview line count agrees with
the preview's own natural width — a measurer that keeps text wider than the box on one
line has not wrapped it (0.6.0 did that to CJK, and it passed as (b)). `spec.json`
`known` lists measured differences the preview does not reproduce, as
`"<version> <name>": reason`; they are classified (a), and a known row that matches
fails the run, so a stale entry cannot linger.

The Standard text generator's height rule (found on 6000.0's editor, which uses Standard; item T found it on the
runtime panel of both versions too, so it is the generator's, not the version's) differs from Advanced (the 6.3
editor) in two measured ways. A Standard row is explained against the Advanced reference, the 6.3 editor set: an exact
integer is rounded up by one (fonts whose ascent − descent equals the point
size, Jua and DungGeunMo), and extra lines advance by FaceInfo `lineHeight`
rather than ascent − descent (only Jua, where the two differ).
