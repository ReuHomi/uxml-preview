## 2. 묶음 A의 범위

**넣는다**

1. `RenderOptions.theme?: 'runtime' | 'editor'`, 기본 `'runtime'`. `RenderResult.theme`에 실제로 쓴 테마
2. 내장 테마 시트를 테마별 둘로. 값은 전부 덤프에서 [확인]:

| | 에디터(`probe-editor-070`) | 런타임(`probe-panel`) |
|---|---|---|
| 기본 글자 크기·색 | 12px, #d2d2d2 | 14px, #1b1b1b |
| Label 바깥/안쪽 여백 | 0 / 0·2·0·1 | 4·4·2·2 / 4·2·4·1 |
| Button 바깥/안쪽/테두리 | 1·3 / 1·6 / 1 #303030, 모서리 3, 배경 #585858, 글자 #eeeeee | 2·4 / 10·12 / 1 #959595, 모서리 0, 배경 #bcbcbc, 글자 #1b1b1b |
| Button 올림·누름·포커스 | #676767 · #46607c(테두리 #0d0d0d) · 테두리 #7baefa | #d1d1d1(#808080) · #959595(#646464) · 테두리 #006aa6 |
| 비활성 Button 배경 | 덤프에서 읽음 | #959595 |
| 글자 요소 `flex-shrink` | 0 | 0 |
| 비활성 투명도 | `enabled="false"`를 쓴 요소만 0.5 | 같음 |

3. 중첩 비활성: 자손이 0.25로 겹치는 지금 규칙을 고친다(두 테마)
4. 테마별 측정 버전: `THEME_UNITY_VERSION` 하나를 테마마다. 런타임 값은 6000.0·6.3이 같다 [확인]
5. 정확도: **에디터 테마의 기존 좌표 세트(660/676, 6000.0)는 그대로 유지**. 런타임은 새 세트로 따로 낸다(골든 44케이스 × 런타임 패널 6.3). 합산하지 않는다
6. 문서: CHANGELOG(기본값 변경을 첫 항목으로), accuracy(런타임 세트 신설), supported, backlog 정정(`pre` 판정 뒤집힘, 중첩 비활성·`flex-shrink` 완료)

**넣지 않는다**: 새 컨트롤 렌더러(묶음 B–F), 리치 텍스트 그리기, 패널 배율, 프로젝트 자체 테마 파일, VSCode·스킬 쪽 변경.

## 6. 위험

- **패널 뒤 배경**: Unity 런타임 패널 자체는 배경이 투명하다(게임 카메라 화면이 뒤에 보인다) [확인 root 배경 투명]. 런타임 테마의 글자는 어두워서, 어두운 배경 위에 그리는 소비자에서는 안 보일 수 있다
- 기본값 전환은 소비자의 스냅숏을 모두 바꾼다. 소비자 갱신은 이 저장소의 범위가 아니므로, CHANGELOG에 바뀌는 값을 구체적으로 적어 소비자가 판단하게 한다
- 에디터 테마의 상태 색은 강제 의사 상태로 쟀다. 실제 마우스 상태와 같다는 것은 UI Builder 화면으로만 봤다(색 숫자 대조는 아님)
- Codex 라운드 상한 3: 단계마다 따로 센다. A2가 3라운드에 안 끝나면 멈추고 보고한다

## 7. 묶음 A를 시작하기 전에 정할 것 (화면 기준)

1. **게임 테마 화면의 바탕색**: Unity 게임 화면에서 UI 뒤는 비어 있고 게임 장면이 보인다. 미리보기는 (가) Unity처럼 바탕을 비워 둘까,
   (나) 런타임 테마일 때 밝은 회색 같은 기본 바탕을 깔까? 비워 두면 어두운 편집기 화면에서 어두운 글자가 잘 안 보인다
2. **에디터 테마 이름**: 에디터의 어두운 화면 하나만 `'editor'`로 둔다. 밝은 에디터 화면은 0.7.0에서 다루지 않는다 — 이대로 괜찮은가?
3. **기존 테스트의 옮김**: 기본값 전환(A3)에서 깨지는 기존 테스트는 기대값을 그대로 두고 "에디터 테마로 그린다"는 설정 한 줄만 더한다.
   고정 테스트의 기대값이 아니라 설정을 바꾸는 것인데, 이 범위의 수정을 미리 허락해 줄 수 있는가? (아니면 A3에서 목록을 보고 결정)
4. **README의 정확도 줄**: 지금은 에디터 테마 기준 숫자(660/676)다. 기본 화면이 런타임으로 바뀐 뒤에도 README는 에디터 기준 숫자를 유지하고
   런타임 숫자를 줄 하나로 더할까, 런타임 숫자를 첫 줄로 올릴까?

## 9. A0 결과 (2026-10-17)

**PanelDump 검증** [확인]. `PanelDump`에 `-panelSize 400x300`과 `-panelSkin editor`(테마 대신 에디터 어두운 공통 시트)를 넣고 골든 44케이스를 떴다.
`UxmlLayoutDump`(커밋된 `tests/layout/unity/<v>/golden/`)와 **6000.0.40f1 1012/1012, 6000.3.25f1 1012/1012 값이 같다.** 이름·순서까지 같고, 남은 차이가 없다.
`tests/golden/panel-dump.test.ts`가 이것을 고정한다(변이 4개 중 3개 실패 확인, 남은 하나는 덤프 값이 모두 정수라 같은 결과를 내는 정수 반올림 변이).

| 확인 | 결과 |
|---|---|
| 덤퍼 결함 | 이전 `PanelDump`는 케이스마다 루트의 스타일시트를 비우지 않았다. 고친 덤퍼로 `probe-panel/`을 다시 떴더니 두 버전 모두 박스·resolved style이 전부 같았다(6.3 박스 1684/1684·스타일 35364/35364, 6000.0 1600/1600·32000/32000). 이전 덤프의 값은 그대로 쓸 수 있다 |
| 이전 `golden-panel/` | 800×600으로 떠 있었다. 400×300으로 교체. 차이는 패널 폭으로 크기가 정해지는 18값뿐(`align-items`·`justify-content`·`direction-*`·`no-margin-collapse`) |
| 버전 | 런타임 패널 좌표는 6000.0.40f1과 6.3이 같다 |

**런타임 골든 세트**: `tests/golden/unity-runtime/`(6.3, 44케이스, `tools/panel-to-golden.mjs`로 생성).

**구현 전 기준선** (지금 코어 = 에디터 테마 값, 정확도 수치와 같은 비교 범위):

| 세트 | 값 | 케이스 |
|---|---|---|
| 에디터(`tests/golden/unity/`, 6000.0) | 660/676 (공개 수치 재현) | 38/40 |
| 런타임(`tests/golden/unity-runtime/`, 6.3) | **609/676** | 31/40 |

테마로 움직이는 Unity 값 125개의 내역: 50개는 비교에서 빼는 스크롤바 부품(`NOT_REPRODUCED`), 13개는 글자 폭을 재는 케이스(비교 범위 밖), **62개가 비교 범위 안**이다.
런타임 기준선의 차이 67개 = 이 62개 + 에디터에서도 틀리는 값(`percent-without-parent-size` 2개, `inventory` 경계) 일부.

**계획에 없던 런타임 값**: 런타임 테마의 세로 스크롤바 폭이 **24px**다(에디터 13px) [확인 `golden-panel/scrollview-overflowing`]. `scrollview-overflowing` 5값과 `inventory`의 뷰포트·슬롯 줄바꿈이 여기서 온다. A2 값 표에 더한다.

**A3 예측 고침** (A0 숫자로): 런타임 세트 **609 → 655/676 이상**. 에디터와 같이 남는 것은 `percent-without-parent-size` 2개와 `inventory` 경계 값으로 본다. 에디터 세트는 660 → 662/676 그대로.

## 19. 일정 — 항목 T(런타임 텍스트 코호트)와 묶음 D (2026-10-17, 사람 지시)

**T. 텍스트 코호트의 런타임판 — 묶음 G 전에 끝낸다(D–F와 순서는 자유).**
0.6.x 텍스트 코호트(줄 92/92, 높이 84/92, 너비 92/92)는 에디터 창에서 쟀다. 0.7.0의 기본은 런타임 테마이고, 런타임 패널에서 글자 폭·높이·줄 수가
맞는지는 측정된 적이 없다. README의 텍스트 수치가 기본 화면에서도 성립하는지 확인한다.
- 같은 코호트(문장·폰트·크기·경계 케이스)를 PanelDump로 런타임 패널에서 덤프(두 버전)
- 미리보기를 `theme: 'runtime'`으로 돌려 같은 기준(줄 수 일치, 높이 일치, 너비 1px 또는 1%)으로 판정
