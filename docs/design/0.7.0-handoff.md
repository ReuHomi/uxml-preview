## 2. 바탕: 코어는 투명, 글자는 어둡다

- 코어는 패널 뒤를 칠하지 않는다. Unity 런타임 패널도 뒤가 비어 게임 화면이 보인다 [확인 root 배경 투명].
- 런타임 테마의 글자는 #1b1b1b다. **어두운 바탕(VSCode 어두운 테마 등)에 그대로 올리면 글자가 거의 안 보인다** [추론].
- 바탕을 무엇으로 채울지는 화면을 보여 주는 쪽이 정한다. 이 저장소의 플레이그라운드는 런타임 테마일 때 패널 뒤에 투명을 뜻하는 체크무늬(흰색·#cccccc)를 깐다. 에디터 테마는 예전처럼 어두운 바탕이다.
- 예전 모습이 필요하면 `theme: 'editor'`를 넘긴다. 다만 0.6.1과 똑같지는 않다(에디터 테마 값이 측정값으로 채워졌다).

## 3. 소비자 영향 측정 [확인, 2026-10-17]

방법: 각 저장소를 스크래치에 복제하고, npm의 `uxml-preview@0.6.1`과 이 브랜치로 만든 tarball을 차례로 설치해 테스트를 돌렸다. 원본 저장소는 건드리지 않았다.

| 소비자 | 커밋 | 0.6.1 | 0.7.0(이 브랜치) | 차이 |
|---|---|---|---|---|
| uxml-author | `d430ff3`(0.2.1, 코어 0.5.1 번들) | conditions 10, exitcodes 5, docs 2 실패, binding 통과 | **같은 17건**(항목 동일) | 번들 크기 문구만(256 KB/4330줄 → 259 KB/4437줄). 17건은 0.6.0부터 있던 미갱신분(설계 보고 9절) |
| vscode-uxml-preview | `ce8ea27`(의존 `^0.5.1`) | tsc 통과, vitest 1 실패(145/146) | tsc 통과, vitest **4 실패**(142/146) | 새 3건 모두 `test/webview.test.ts`의 진단 패널 개수: Label 하나뿐인 문서에서 테마 경고가 "1 issue"로 세어진다("0 unsupported · 3 known divergences" 기대), "Renderer differences from Unity" 3 → 4 |

- 두 소비자의 테스트는 **색·여백·글자 크기를 단언하지 않는다**. 기본 테마가 바뀌어 화면 모양이 달라지는 것(글자색, Label 여백, 14px)은 테스트로 드러나지 않았고, 사람의 F5 확인이 필요하다 [추론].
- uxml-author의 exit 코드 판정식(`not-rendered` + `affectsLayout` → 3)에는 새 영향이 없다. 테마 경고는 `version-dependent`라 그 조건에 걸리지 않는다 [확인 exitcodes 결과 동일].

## 4. 소비자가 판단할 것 (제안 아님, 목록)

1. 바탕: 런타임 테마에서 어두운 글자가 보이도록 패널 뒤를 무엇으로 칠할지
2. 테마 선택: 사용자에게 `runtime`/`editor`를 고르게 할지, 하나로 고정할지
3. 테마 경고: `version-dependent` "Built-in control defaults applied"를 issue로 셀지, 알림으로 둘지
4. 스냅숏·픽스처: 기본 테마로 그린 기대 화면이 있으면 다시 만들지, `theme: 'editor'`로 고정할지

## 5. 코어 쪽에 남은 질문 (이 저장소)

- **런타임 테마에서 테마 경고가 필요한가.** 런타임 값은 6000.0.40f1과 6.3이 같았다 [확인]. "measured on Unity 6000.3.25f1"는 사실이지만, 버전에 따라 달라진다는 근거가 없는 상태에서 Label이 있는 모든 문서에 붙는다. 경고를 줄일지는 사람 결정 대기.
