### 1-2. 새로 그리는 컨트롤 (묶음 B–F)

`supportedControlNames()`가 5종에서 **15종**으로: `VisualElement` `Label` `Button` `Image` `ScrollView` + `GroupBox` `Box`(B), `TextField`(C), `Slider` `SliderInt`(D), `Toggle` `RadioButton`(E), `ProgressBar` `TextElement` `RepeatButton`(F). 이 컨트롤들은 더는 `unsupported-control` 경고를 내지 않고, Unity의 부품(이름·클래스)을 만든다. RepeatButton은 Unity처럼 **맨 글자**로 보인다(버튼 모양이 아니다). 에디터 테마의 Toggle 상자는 Unity 그림에서 잰 색으로 칠한다.

### 1-3. 동작 변화 (화면이 달라질 수 있는 것)

| 변화 | 내용 | 근거 |
|---|---|---|
| 글자 측정 — 생성기 규칙 | `-unity-text-generator`가 standard인 글(런타임 테마의 기본)은 Standard 규칙으로 잰다: 높이 `floor(fs·r + (n−1)·fs·lineHeight/pointSize) + 1`, 폭은 커닝 없이, 그릴 때 `font-kerning: none`. advanced(에디터 테마의 기본)는 그대로. **테마가 아니라 해석된 값**으로 고른다 | 텍스트 코호트 덤프, 계획 29절 |
| 글자 자르기(폭) | 받은 폭보다 넓은 글은 그 폭으로 잘린다. 절대 위치와 TextField 안쪽 글은 자르지 않는다 | `g-clamp` 덤프 |
| 글자 자르기(높이) | 받은 높이보다 높은 글은 그 높이로 잘린다(안쪽 여백·테두리 아래로는 줄지 않음). TextField 안쪽 글도 자른다 | `g-clamp-h` 덤프 |

| 공개 API 추가 | `textHeight(lines, fontSize, face, paragraphBreaks?, paragraphSpacing?, generator?)` — 여섯째 인자(선택). 빼면 지금처럼 advanced | — |

## 2. 바탕: 코어는 투명, 글자는 어둡다

- 코어는 패널 뒤를 칠하지 않는다. Unity 런타임 패널도 뒤가 비어 게임 화면이 보인다 [확인 root 배경 투명].
- 런타임 테마의 글자는 #1b1b1b다. **어두운 바탕(VSCode 어두운 테마 등)에 그대로 올리면 글자가 거의 안 보인다** [추론].
- 바탕을 무엇으로 채울지는 화면을 보여 주는 쪽이 정한다. 이 저장소의 플레이그라운드는 런타임 테마일 때 체크무늬(흰색·#cccccc)를 깐다.
- 예전 모습이 필요하면 `theme: 'editor'`를 넘긴다. 다만 0.6.1과 똑같지는 않다(에디터 테마 값이 측정값으로 채워졌다).

## 5. 코어 쪽에 남은 질문 (이 저장소)

- **`:root` 경고의 kind — 바꾸지 않는다(2026-10-17 사람 결정).** 소비자는 reason을 기준으로 읽는다 [확인 코드 읽기]. 할 일 없음.
- **알려진 차이**(supported·accuracy): 스크롤바 미표시, 반 픽셀 반올림(가운데 정렬 글 x 1px), 지정한 글꼴에 없는 글자가 마지막 줄 맨 앞일 때 런타임 상자 2px(`noto-jp-zh-20-w60`, `known` (a), `tests/text-cohort/fallback-zh/`), Unity 쪽 같은 글 오염 현상.
