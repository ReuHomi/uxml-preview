# Architecture

```
        UXML 텍스트        USS 텍스트
             │                 │
             ▼                 ▼
      ┌──────────────────────────────┐
```

## 핵심 설계 결정

### 1. 레이아웃은 Yoga에 위임

Unity UI Toolkit은 Flexbox의 부분집합을 구현한 Yoga를 레이아웃 엔진으로 사용한다.
직접 구현하면 미묘한 차이가 누적되어 반드시 어긋난다.

`yoga-layout` npm 패키지가 공식 WebAssembly 빌드를 제공하므로 그대로 쓴다.

**주의**
- ESM + top-level await 필요. 미지원 환경 대비로 `yoga-layout/load` 경유 로드도 지원
- Yoga 노드는 자동 GC되지 않는다. `freeRecursive()` 호출 필수

### 2. 캔버스가 아니라 DOM으로 그린다

Yoga가 계산한 좌표에 `position: absolute` div를 배치하고, 시각 속성만 CSS로 변환한다.

**이유**
- 텍스트 렌더링·폰트·안티앨리어싱을 브라우저에 맡길 수 있다
- 클릭 판정, 스크롤, 접근성이 따라온다
- 편집 레이어에서 DOM 이벤트를 그대로 쓸 수 있다

**주의**
- 모든 요소에 `box-sizing: border-box` (USS는 항상 border-box 동작)
- `z-index`를 출력하지 않는다 (USS에 없음, 형제 순서로 결정)

### 3. 계산된 값에는 출처가 따라붙고, 계산 결과는 모델 밖에 둔다

출처가 필요한 이유는 편집 기능(Phase 8)이다. 사용자가 화면에서 색을 바꿨을 때
인라인 스타일에 쓸지, 어느 USS 규칙을 고칠지를 출처 정보로 판단한다.
표현은 `StyleOrigin` — `src/model/types.ts` 참조.

**단 계산 결과 자체는 모델에 저장하지 않는다.** 저장하면 USS를 한 줄 고쳤을 때
무엇이 낡았는지 추적해야 하고, 그 추적을 한 번이라도 틀리면 사용자에게 틀린 값을
보여준다. 낡을 수 있는 데이터를 아예 만들지 않는 쪽이 안전하다.

후보 목록("어느 규칙들이 경쟁했나")도 저장하지 않는다. 화면을 그릴 때 쓰는 계산기를
해당 요소에 다시 돌려서 얻는다. 승자를 정하는 로직이 하나뿐이라 두 답이 어긋날 수 없다.

이 절은 모델 전체를 관통하는 원칙의 한 사례다 —
**모델에는 파일에서 온 것만 넣고, 계산해서 알 수 있는 것은 넣지 않는다.**
줄 번호, 펼친 shorthand, "이 컨트롤을 지원하는가"가 전부 같은 이유로 모델 밖이다.

### 3-b. 파서를 직접 쓴다 (`DOMParser`를 쓰지 않는다)

`DOMParser`는 소스 위치를 주지 않는다. 표준 DOM에 그런 API가 없다.
스팬 재출력은 요소마다 여는 태그·안쪽·닫는 태그의 오프셋을 요구하므로
DOMParser로는 성립하지 않는다.

대신 우리 스캐너는 **해석하지 않고 위치만 찾으면 된다.** 속성 값은 엔티티를
디코딩하지 않고 날것으로 두고, USS 선언 값도 문자열 그대로 둔다. 일반 XML/CSS
파서보다 훨씬 좁은 문제다.

### 4. 왕복 보존

`serialize(parse(x))`가 `x`와 같아야 한다.
주석, 속성 순서, 들여쓰기가 유실되면 실무에서 못 쓴다.

기준: **사람이 열었다 저장했을 때 git diff가 깨끗한가.**

### 5. 에셋 경로 리졸버

`background-image`가 `url("project://database/Assets/...")` 또는 `resource("...")`
형식이라 브라우저가 로드할 수 없다.

```ts
render(doc, el, {
  resolveAsset: (path: string) => string | null
});
```

라이브러리 사용자가 자기 환경에 맞게 구현한다.
리졸브 실패 시 플레이스홀더를 그리고 경고 목록에 담는다.

## 디렉토리

```
src/
├── index.ts          공개 API
├── model/            데이터 모델 정의
├── parser/           UXML·USS → 모델
├── serializer/       모델 → UXML·USS
├── style/            셀렉터 매칭·우선순위·캐스케이드
├── layout/           Yoga 브리지·텍스트 측정
├── render/           DOM 페인팅·CSS 매핑
└── controls/         컨트롤 타입 정의
```
